# Перенос в реальный Klipper Farm

## Статус и границы

Архив передаёт утверждённый вид и демонстрационное поведение раздела пластика. Доступ к приложению, его базе, текущему API и сборке при подготовке архива не использовался. Фреймворк и схему данных нужно определить по актуальному проекту. Это не повод писать второй независимый склад: новый интерфейс должен использовать уже существующий источник данных.

`approved/approved-source.html` — неизменяемый ориентир для сравнения, SHA-256 `0167dad35ed11d74b5febf989e0a19f96282c27fdae2302599102a501001e24d`. Разделённые CSS, HTML и JS извлечены из него. `approved/preview.html` — самостоятельная оболочка для просмотра: локальные базовые стили, значки Lucide и подсказки встроены в файл, CDN не требуется. Эту оболочку и её iframe/runtime не надо переносить в приложение.

`renderer/spool-viewer.mjs` и `.js` — подготовленный для переноса рендерер. Из него удалён демонстрационный склад, добавлены явные входные данные, методы обновления, управление жизненным циклом и необязательные поля этикетки. На контрольных данных его изображение сверено с исходником. Результат проверки находится в `checks/verification.json`.

## Утверждённый вид

- Широкие чёрные спицы и широкий обод. В архиве только версия, к которой пользователь попросил вернуться.
- Детализированная чёрная катушка: фаски, посадочные элементы, небольшие металлические детали, печать на ободе, бумажная этикетка.
- Цветная намотка с отдельными витками, торцевой спиралью, переходом верхнего витка и закреплённым концом нити.
- Освещение с бликами и тенями; варианты поверхности Silk, обычная и матовая; цвет затрагивает пластик.
- Объём намотки зависит от доли оставшейся массы. Пустая катушка остаётся видимой.
- По умолчанию видна общая карточка, кнопка «Крупно» открывает просмотр катушки. Поворот доступен перетаскиванием и кнопками, увеличение — в крупном просмотре.
- Контрольный ракурс: `yaw: -0.80`, `pitch: 0.21`, `roll: -0.075`, `zoom: 1`.

Не требуется снова менять геометрию или улучшать детализацию перед переносом. Сначала воспроизвести утверждённый результат в приложении. Физические размеры модели условные; это иллюстрация учётных данных, а не измерение массы по изображению и не модель для печати STL.

## Данные приложения

| Вход рендерера | Что брать из приложения |
| --- | --- |
| `id` | Стабильный идентификатор конкретной катушки. Не индекс её строки в списке. |
| `material` | Материал: PLA, PETG, ABS, TPU либо название из текущей модели. |
| `color` | Цвет пластика в формате `#RRGGBB`. |
| `grams` | Реальный остаток материала в граммах, без массы пустой тары. |
| `capacityGrams` | Номинальная масса материала полной катушки; по умолчанию 1000 г. |
| `diameterMM` | Диаметр нити; по умолчанию 1.75 мм. Геометрия иллюстративная; поле меняет маркировку. |
| `finish` | `silk`, `normal`, `matte` либо число от 0 до 1. |
| `serial` | Реальный отображаемый номер катушки; необязателен. |
| `lot` | Реальная партия; необязательна. |
| `ordinal` | Необязательный целый печатный номер 1…9999. Не использовать как ID. |
| `barcode` | Необязательный настоящий EAN-8 с корректной контрольной цифрой. Другие типы здесь не рисуются. |

Если серийного номера, партии или EAN-8 нет, поля не передавать. Рендерер не придумывает их. Пример `spool-descriptor.json` повторяет декоративные данные исходного макета исключительно для визуального сравнения. Привязка к принтеру, имя цвета, хранение, учёт расходов и агрегаты находятся в приложении, а не в 3D-модуле.

Внутри рендерера масса переводится в долю `min(1, grams / capacityGrams)`. Значение выше ёмкости показывается как полная катушка, при этом реальные `grams` сохраняются в состоянии модуля без обрезания. Исправление некорректных данных — задача приложения. Отрицательные/нечисловые остатки, неположительная ёмкость и некорректные цвета отвергаются.

## Общий запас

Показывать отдельно:

1. Общую массу всех учтённых катушек в килограммах, включая установленные на принтерах.
2. Количество непустых катушек (`grams > 0`), из них на принтерах и свободных на складе.
3. Массу и количество по материалам.
4. Остаток выбранной катушки в граммах и её ёмкость.

Каждый ID участвует в общей сумме один раз: установка на принтер — это смена местоположения, а не копирование записи. Суммы считать из исходных значений в граммах, округлять только отображение килограммов. Пустые катушки сохраняются в учёте, но не добавляются к счётчику доступного непустого запаса. Если приложение различает удалённые, списанные или архивные записи, использовать его существующие правила и явно обозначать смысл итогов. Отсутствующие/ошибочные остатки обрабатывать как проблему данных, не подменять демонстрационными числами.

## Установка и замена

Предпочтительно использовать текущую серверную/локальную транзакцию приложения. В одной операции: проверить существование принтера и катушки, её доступность и положительный остаток; снять предыдущую катушку на склад; назначить новую; сохранить; обновить подписанные представления из одного результата. Не допускать назначения одной катушки двум принтерам. При конфликте или ошибке записи сохранить согласованное состояние и показать ошибку.

Отмена не меняет данные. Установка/снятие не расходуют пластик, не обнуляют старую катушку и не меняют сумму масс. При расходе или ручной коррекции остатка все итоги, миниатюры и карточки принтеров обновляются из одного состояния. Ползунок в макете — инструмент демонстрации; способ коррекции реального остатка определяется существующим интерфейсом учёта приложения.

## Подключение рендерера

Для сборщика приложения:

```js
import { createFilamentSpool } from './spool-viewer.mjs';

const viewer = createFilamentSpool(canvas, {
  spool: descriptorFromApplication,
  mode: 'card',
  pixelRatioCap: 2,
  onError(error) { showCachedImageAndError(error); }
});

// После получения новых реальных данных:
viewer.setSpool(nextDescriptorFromApplication);

// При переключении на крупный просмотр и изменении размеров контейнера:
viewer.setMode('inspect');
viewer.resize();

// При уходе с экрана / размонтировании:
viewer.destroy();
```

У canvas должны быть заданные CSS-ширина и высота, например `width:100%;height:394px;display:block`. Для компонента применять ref и штатный lifecycle своего фреймворка; не искать canvas по глобальному ID. Кнопки поворота, масштаб, выбор цвета и учётные операции остаются UI-компонентом приложения.

Для обычного `<script>` подключить `spool-viewer.js` и вызвать `KlipperFilamentSpool.create(canvas, options)`. Два файла рендерера содержат одинаковую реализацию; одновременно подключать их не требуется. `.mjs` предназначен для приложения/сборщика или HTTP-сервера; пример двойным щелчком использует классический `.js`, чтобы не зависеть от ограничений модулей на `file://`.

| Метод | Поведение |
| --- | --- |
| `setSpool(descriptor)` | Полностью заменить описание, обновить геометрию, цвет, маркировку и доступное имя. |
| `updateSpool(patch)` | Обновить часть полей текущего описания. |
| `setView({yaw,pitch,roll,zoom})` | Поворот в радианах; `pitch` ограничен ±1.1, масштаб 0.8…1.9. |
| `setMode('card' / 'inspect')` | Изменить режим плотности пикселей. Размер и раскладку задаёт приложение. |
| `resize()` | Перерисовать по текущим CSS-размерам canvas. ResizeObserver также подключён. |
| `captureThumbnail(size = 160)` | Получить PNG data URL размером 32…1024; затем восстановить основной рендер. Миниатюра без тяжёлого постпроцесса и тени пола. |
| `getState()` | Копия описания, ракурс, режим, число вершин, флаги уничтожения/потери контекста. |
| `destroy()` | Снять события и observer, отменить кадр ввода, освободить GPU-ресурсы. Повторный вызов допустим. |

`interactive:false` отключает перетаскивание. `pixelRatioCap:1` снижает разрешение для слабого устройства. `releaseContextOnDestroy:false` оставляет сам контекст, освобождая ресурсы, если canvas будет использован снова. По умолчанию контекст после `destroy` освобождается через `WEBGL_lose_context`, когда расширение доступно.

Создание может выбросить исключение, если WebGL недоступен или входные данные неверны, — обернуть в `try/catch`. `onError` сообщает о потере/восстановлении WebGL-контекста; после потери показать миниатюру, уничтожить старый экземпляр и создать новый на новом canvas при восстановлении/повторном открытии. Самовосстановление ресурсов внутри модуля не реализовано. После уничтожения обновлять старый экземпляр нельзя.

Для доступности остаются текстовые поля материала, остатка, назначения и обычные кнопки; 3D не должен быть единственным способом прочитать данные. Модуль задаёт canvas `role="img"` и `aria-label` с массой, но клавиатурное управление и подписи кнопок реализуются оболочкой.

## Производительность и согласованность

Геометрия подробная: около миллиона вершин для контрольного варианта. Это не готовый к массовому созданию контекст для каждой строки. Держать один активный подробный WebGL-просмотр; для остальных карточек применять PNG-миниатюры, сделанные тем же рендерером. Кэш ограничивать по размеру и сбрасывать при изменении отображаемых данных; в ключ включать ID, материал, цвет, остаток, ёмкость, поверхность, маркировку, ракурс и версию рендерера. Генерировать миниатюры последовательно и не перехватывать текущий просмотр во время перетаскивания.

Непрерывного цикла анимации нет. Рендер вызывается при изменении данных, размеров или ввода; pointermove объединяется в один requestAnimationFrame. На перетаскивании отключается тяжёлый постпроцесс и возвращается после отпускания. SSAO/сглаживание используют доступное расширение depth texture. Без него остаётся базовый рендер. Скорость и память нужно проверить в реальном Windows-приложении на его GPU/встроенном браузере.

Стили карточки используют `light-dark()` и `color-mix()`, как исходный макет. Сопоставить их с темой и поддержкой движка приложения; при необходимости заменить на существующие светлые/тёмные токены. Для небольших карточек принтеров сохранить реальную цветовую маркировку и читаемые остатки; не обязательно помещать полную форму склада внутрь каждой карточки.

## Порядок работы в следующем чате

1. Открыть актуальный проект, прочитать применимые правила, найти текущие компоненты и состояние склада/принтеров. Сохранить несвязанные изменения пользователя.
2. Сопоставить поля, подключить существующий источник данных, итоги и назначение.
3. Встроить катушку с управлением lifecycle, затем переносить визуальную карточку и замены.
4. Проверить сценарии из `03-VERIFIED-RU.md` в приложении, выполнить его штатные проверки и сборку.
5. Показать пользователю результат и фактическую валидацию. Не заявлять о готовом установщике или опубликованном релизе без их создания и проверки.
