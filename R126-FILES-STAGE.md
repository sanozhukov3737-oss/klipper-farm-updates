## Что исправлено

- `MoonrakerClient.fileEntries()` запрашивает `server.files.list` через существующий RPC, с `root=gcodes`. Обычный массив и обёртка `result` обрабатываются одинаково.
- При HTTP 404/405 или отсутствии RPC-метода выполняется рекурсивное чтение `/server/files/directory?path=gcodes...`. Отдельный вызов старого REST `/server/files/list?root=gcodes` из интерфейса больше не используется.
- Вложенные папки, русские имена, пробелы, символы `#` и `%`, размеры в байтах и дробные даты изменения сохраняются. Пути каталогов и скачивания кодируются отдельно.
- Список с некорректной строкой, противоречивым дублем, признаком `partial`/`truncated`/`complete=false`, ошибкой дочерней папки или превышением лимита отклоняется целиком. Прежний кэш, проекты, хеши и результаты проверки при этом остаются в базе.
- HTTP 401/403, тайм-ауты и ошибки 5xx не вызывают резервного обхода списка и остаются видимыми. Ошибка чтения локальной базы больше не считается пустым кэшем, а первая запись нового списка ожидает подтверждения базы.
- Ошибки чтения метаданных показываются в интерфейсе и отчёте проверки. Отсутствие необязательных метаданных по HTTP 404/405 по-прежнему позволяет проверить сам G-code.
- Ошибка загрузки текста G-code содержит исходную причину в блокирующем отчёте. Совместимость проверяется тем же валидатором, включая границы Flashforge, заголовок модели, команды Creality и опасные команды.
- После успешной проверки выбранный путь передаётся существующему `MoonrakerClient.start()` → `printer.print.start`; механизм запуска не заменён.
