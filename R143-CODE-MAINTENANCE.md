# R143 — обслуживание кода и производительность

Кандидат поверх опубликованного R142. Стабильный канал пока остаётся на R142.

Реализовано: освобождение MJPEG и WebRTC при закрытии камеры, компактные временные буферы геометрии катушки, удаление 690 перекрытых CSS-объявлений, отдельный модуль 16 команд локальной библиотеки и общий модуль обмена с нативными акторами.

Локально прошли TypeScript, production-сборка, проверки печати и учёта пластика, 132 унаследованных сценария логики, 30 сравнений оформления и 6 сравнений реальных GPU-буферов катушки. Нативные тела команд и остальной сетевой клиент восстановлены для сравнения и совпадают с R142.

В 90-секундном Linux/Chromium тесте TV R142 сохранил 6 открытых видеопотоков после закрытия и достиг только 6 камер. Кандидат открыл все 7 камер по очереди и оставил 0 потоков после закрытия. Это синтетические локальные MJPEG-потоки, физические принтеры не подключались.

В предварительном сравнении 3D-катушки пик JavaScript, backing storage и embedder allocations снизился с 124692766 до 74369892 байт. Это отдельные управляемые выделения renderer, а не общая память приложения. Самплер всей памяти процессов в этой среде недоступен. Windows-проверка установленного приложения ещё предстоит.

Команды проверки: `npm run check:spool-buffer`, `npm run check:spool-appearance`, `npm run check:theme-equivalence`, `npm run check:performance`, `npm run check:module-boundaries`. Для сравнений задайте `KF_PERF_BASELINE_SOURCE` на распакованные исходники R142. Установите `ui-tests` и укажите `CHROMIUM_EXECUTABLE`, если браузер не установлен Playwright.

Пакет `r143-source-changes.json` содержит точные изменения поверх `KF-R142-FULL.zip`. `apply-r143-maintenance.py` проверяет SHA-256 архива, исходных и новых файлов и сохранение остальных файлов. Windows-процесс сборки и браузерных проверок разделены на независимые задания; публикация в нём отсутствует.
