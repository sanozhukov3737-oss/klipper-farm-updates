# Правила оверлеев

Оверлей — это `rNNN-<тема>/` с `apply.py`, `source-manifest.json` и каталогом `changes/`. CI
раскладывает его поверх точного кандидата и применяет по порядку номеров.

Правило одно и главное: **оверлей несёт только исходники.**

## Почему

`dist/` собирается workflow из только что применённых исходников. Если положить `dist/` в payload,
устаревший бандл поедет вместе с правкой исходников и переживёт её. Кроме того `BUILD-PROVENANCE.json`
хранит хеш входных файлов `src/` — любой такой файл в оверлее делает его недействительным, и
проверки честно скажут «Frontend was not built from the packaged source». Доставлять надо причину
сборки, а не её результат.

`target/`, `node_modules/`, `__pycache__/`, `*.exe`, `*.pyc` — то же самое: их нельзя прочитать как
исходник, их нельзя осмысленно проверить на ревью, и в git они занимают место навсегда.

## Что проверяется

```
python verify-overlays.py .
```

| Правило | Что именно |
|---|---|
форма пути | относительный, POSIX-разделители, без `..`, без абсолютных путей |
нет build-выхода | ни в манифесте, ни в payload: `dist/`, `target/`, `node_modules/`, `binaries/`, `__pycache__/`, `.cache/`, `coverage/`, `BUILD-PROVENANCE.json`, `DIST-V20-LOCK.json`, `*.exe`, `*.dll`, `*.pdb`, `*.rlib`, `*.pyc`, `*.zip`, `*.log` и подобное |
payload = манифест | payload содержит ровно объявленные файлы: ни лишних, ни пропавших |
целостность | `sha256` совпадает после канонизации CRLF/LF; `bytes`, если указан, — длина после канонизации |

Проверяется каждый каталог с `source-manifest.json`, поэтому новые оверлеи покрываются без правки
скрипта.

**Чего правило не требует:** `buildId` не обязан совпадать с `baseBuildId` — оверлеи
`*-release-sequence` (r155, r160, r184, …) законно двигают его вперёд. Манифесты без поля `schema`
считаются историческими: их не переписываем.

## Как выглядит нарушение

```
r199-stress-effective: scripts/__pycache__/silero-synthesize.cpython-312.pyc:
  is build output: "__pycache__/" is generated, not authored
```

## Известное нарушение

`r199-stress-effective/changes/scripts/__pycache__/silero-synthesize.cpython-312.pyc` — 162 КБ
байткода Python, закоммиченные в payload и не объявленные в манифесте. `apply.py` его не копирует
(он берёт только объявленные пути), поэтому на сборку это не влияет, но в репозитории он лишний.
Пока файл не удалён, `verify-overlays.py` завершается с кодом 1.

## Порядок проверки перед коммитом оверлея

```
python verify-overlays.py . --quiet     # правило
git status --short                      # в индексе нет dist/, target/, *.exe
```

## Вторая ошибка, которую стоит помнить

В r248–r252 подряд всплывали проверки, которые читали только `lib.rs` и искали маркеры, уехавшие в
`upload_commands.rs`, `permissions.rs`, `app.rs`, `auth_commands.rs`. Каждая падала на первом же
маркере и оставалась красной неделями, потому что сообщение выглядело как посторонняя ошибка.

Если оверлей переносит код между модулями — сразу ищи, кто этот файл читает:

```
grep -rl "доминирующий маркер" scripts/
```
